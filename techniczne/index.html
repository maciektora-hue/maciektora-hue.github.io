Techniczne

Miejsce na narzędzia techniczne używane przy tych projektach oraz krótki opis tego, jak repozytorium jest połączone z usługami zewnętrznymi. Lista poniżej opisuje faktycznie używane elementy, a nie planowaną architekturę.

Narzędzia

Viewer bazy SQL Pokazuje bieżący stan faktycznej bazy Turso: tabele, kolumny, PK, FK, liczbę rekordów i dostępne informacje o rozmiarze. Dane są pobierane na żywo przez API, a nie odtwarzane z dokumentacji w repozytorium.

Co właściwie trzymamy w SQL-u

To nie jest tylko magazyn piosenek. W jednej bazie trzymamy uporządkowane dane potrzebne do analizy muzyki oraz mapowania treści projektów Rosja i AuDHD.

01
Piosenki
Podstawowe informacje o utworach: tytuły, wykonawcy, albumy, kolejność na liście, identyfikatory Spotify i nasze własne identyfikatory. Jest też zapis, czy utwór udało się poprawnie połączyć z tekstem i nagraniem.
02
Teksty piosenek
Pełne teksty przypisane do konkretnych utworów. To z nich później robimy analizę znaczeń, motywów i zmian w czasie.
03
Znaczenia i tagi
Słownik motywów i stanów pojawiających się w tekstach, na przykład samotność, maskowanie, ulga, gniew czy sensoryka. Trzymamy ich definicje, rodziny i osie znaczeniowe oraz informacje o wydźwięku i kierunku znaczenia.
04
Tagi przypisane do tekstów
Dla poszczególnych tekstów zapisujemy, jakie tagi zostały im przypisane i kiedy powstało dane tagowanie. Dzięki temu można szukać wzorców nie tylko w jednej piosence, ale w całej bibliotece.
05
Audio
Informacje o plikach dźwiękowych i ich połączeniu z utworami oraz szczegółowe pomiary brzmienia: głośność, stereo, częstotliwości, barwa, rytm, tempo, tonacja i wiele cech używanych do porównywania nagrań.
06
Rosja i AuDHD
Mapę treści obu działów: jakie mamy dokumenty, jak są podzielone na sekcje, jaka jest ich kolejność i hierarchia, gdzie prowadzą anchory oraz jakie opisy mają poszczególne fragmenty.
07
Słowa kluczowe sekcji
Wspólny słownik pojęć oraz przypisania tych pojęć do sekcji tekstów, między innymi w AuDHD. Pozwala to łączyć różne fragmenty po znaczeniu, nawet gdy są napisane innymi słowami.
Po ludzku:
HTML pokazuje treść człowiekowi. SQL pamięta, co jest czym, co do czego należy, co z czym się łączy i co potem można policzyć albo porównać.

Co jest do czego podłączone

01
GitHub
Główne repozytorium plików projektu: HTML, Python, konfiguracja, dane pomocnicze i historia zmian.
02
GitHub Pages
Publikuje statyczną część serwisu WWW bezpośrednio z repozytorium, w tym strony główne projektów i ten dział techniczny.
03
GitHub Actions
Automaty wykonujące zadania zapisane w .github/workflows: m.in. audyty, operacje na anchorach i inne powtarzalne prace na plikach oraz danych.
04
Render
Hostuje publiczny backend piosenki-api. Pobiera kod z tego repozytorium i uruchamia część serwerową w Pythonie.
05
Flask + Gunicorn
Flask definiuje API i strony generowane po stronie serwera, a Gunicorn uruchamia aplikację jako usługę WWW na Renderze.
06
Turso / libSQL
Zewnętrzna baza zgodna z SQLite. Przechowuje dane SQL; backend łączy się z nią przez bibliotekę libsql. Token dostępu pozostaje w zmiennych środowiskowych Rendera, nie w publicznym HTML.
07
Flask-CORS
Most między statycznym WWW na GitHub Pages a API na Renderze. Pozwala stronom z domeny GitHub Pages odczytywać endpointy /api/*.
Najkrótszy obraz przepływu:
GitHub Pages → Render / Flask → Turso / libSQL. GitHub Actions działa obok tego jako warstwa automatyzacji repozytorium.
